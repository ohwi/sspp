# 한국 클라이언트 대응: 1.1.0-dev1

이 브랜치는 첫 업데이트입니다. 최신 캐릭터 메타데이터와 인식 이미지의 준비 상태를 구분합니다.

| 항목 | 현재 범위 |
|---|---|
| 캐릭터 이름·ID 자료 | SSToy 2026-10-01 커밋의 표시·사용 가능 캐릭터 40명 |
| 잠재력 ID·최대 레벨 자료 | 1,160개 |
| 얼굴 인식 이미지 | 기존 30명 + 윌로(여름) 1명 |
| 잠재력 인식 이미지 | 기존 870개 + 윌로(여름) 3개 |
| 남은 인식 이미지 | 9명의 얼굴과 잠재력 287개 |
| 신규 이미지 확인 | 한국어 1600×900 선택 화면 한 장, 카드 3개 |
| 다른 스킨·화면·해상도 | 새 이미지의 인식은 아직 검증하지 않음 |

게임 패치 번호는 확인하지 못했습니다. 사용자가 실행 중인 최신 한국 서버 클라이언트의 화면을 읽었으며, 앱이 찾은 창 제목은 `StellaSora`였습니다.

## 변경 내용

- SSToy v2d/v3d 링크의 Base91 13/14비트 처리 및 v2 고정 ID 복원을 수정했습니다. 헤더·내부 버전·잘린 데이터·잘못된 ID·추가 데이터·압축 크기를 검사합니다.
- 캐릭터를 영문 이름 대신 고정된 게임 ID로 연결합니다. 현재 `Nazuka`와 기존 이미지 키 `natsuka`도 같은 캐릭터로 처리합니다.
- 마크 4(명함만)는 Lv.1 권장으로 표시합니다. 최대 레벨이 1인 잠재력에 Lv.6 목표를 표시하지 않습니다. 추천은 여전히 빌드에 저장된 고정 우선순위이며 현재 획득 레벨을 읽지는 않습니다.
- 이미지가 부족한 빌드도 전체 데이터를 보존해 저장하며, 가져오기 대화상자와 컨트롤 패널에 누락 항목을 안내합니다. 알 수 없는 캐릭터나 다른 캐릭터의 잠재력은 부분 파일로 저장하지 않습니다.
- 기존 프리셋을 덮어쓰지 않고 같은 이름 뒤에 번호를 붙입니다. 가져온 빌드를 자동 선택합니다.
- 이미지 파일 이름 3개를 실제 잠재력 ID로 바로잡았습니다. 픽셀 내용은 그대로입니다.
- 한글 경로, 대소문자, 캐시의 삭제·이름 변경·내용 교체, 비정상 OpenCV 점수, 보조 모니터 좌표를 처리합니다. 카드 인식 영역의 색상 테두리를 복원했습니다.

## 신규 이미지 출처와 확인

`resources/template_provenance.json`에 원본 화면 SHA256과 추출 좌표를 기록했습니다. 전체 게임 화면은 저장소에 포함하지 않았습니다.

| 위치 | 잠재력 | ID | 저장 화면의 매칭 점수 |
|---|---|---:|---:|
| 왼쪽 | 울려 퍼지는 음파 | 516023 | 0.981832 |
| 가운데 | 해안을 덮치는 격류 | 516022 | 0.986552 |
| 오른쪽 | 흩날리는 물꽃 | 516021 | 0.984624 |

별도의 현재 화면 캡처에서도 세 카드 ID와 예제 빌드 우선순위가 일치했습니다. 그때 카드 점수는 0.905784 / 0.931765 / 0.943601이었습니다. 게임 창의 실제 위치는 (2567, 320), 크기는 1600×900이었습니다. 오버레이를 표시하거나 게임 입력을 보내지는 않았습니다.

위 표의 높은 점수는 이미지 제작과 확인에 같은 화면을 사용했으므로 이 수치는 연결 확인용 결과입니다. 독립 화면에서의 정확도나 일반 성능을 뜻하지 않습니다. 게임 클릭·키 입력은 수행하지 않았습니다.

`willow_capture_demo.json`은 이 카드 3개를 표시하기 위한 인식 확인용 예제입니다. 공략 추천 빌드가 아닙니다.

확인된 파일 이름 수정:

- `freesia/main_13.png` → `512513.png`
- `natsuka/5133-6.png` → `513306.png`
- `mistique/5135008.png` → `513508.png`

잠재력의 한국어 이름·캐릭터·그림은 [고정된 SSToy 자료](https://github.com/JforPlay/sstoy/tree/34f57606015277cf9da76a2c7cc14fa1b68ccbbf/public/data)와 대조했습니다. 웹의 투명 아이콘은 기존 게임 화면 캡처와 구도·배경·역할 기호가 다르므로 나머지 이미지를 단순 축소해서 추가하지 않았습니다.

## 재현

저장소 루트에서 Python 3.11 가상환경을 사용합니다.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r app/requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/update_catalog.py --audit-only
```

이름·ID 자료를 갱신할 때는 특정 40자리 커밋 SHA를 지정합니다. 이 작업은 인식 이미지를 추가하지 않습니다.

```powershell
.\.venv\Scripts\python.exe scripts/update_catalog.py --revision 34f57606015277cf9da76a2c7cc14fa1b68ccbbf
```

## 남은 검증과 지원 제한

- 앱에 등록되지 않은 범위는 얼굴 9명과 잠재력 287개입니다. 고정 공개 자료에 모든 잠재력 ID의 카드·glyph와 모든 캐릭터의 얼굴 계열 원본이 있어, 온라인 자산으로 인식 후보를 생성할 수 있습니다. 후보 생성 이후의 실제 화면 인식 검증과 앱 등록은 별도 작업입니다. 감사 도구는 현재 앱에서 빠진 ID를 출력합니다.
- SSToy raw 링크(`v2r/v3r`) 중 원본 인코더가 문자 `undefined`를 넣어 바이트를 유실한 링크는 복원할 수 없어 명확한 오류를 반환합니다. 정상 raw 링크와의 연동 완료로 보고하지 않습니다. 구형 LZ-String 링크도 지원하지 않습니다.
- GUI와 좌표 렌더링은 Qt offscreen에서 검증했습니다. 사용자 게임 위에서 표시·클릭 투과가 정상인지, 다른 모니터 배율과 전체 화면 방식에서 동작하는지는 별도 실사용 확인이 필요합니다.
