# 경량 도형 모델: 1.1.0-dev6

이전 미인식9개를 해결하려고 카드 하단 도형만 읽는 작은 신경망을 추가했다. 엘리·토나·윌로(여름)의 저장 화면16장을 실제 게임 코드 가져오기→BuildLoader→MatcherWorker.process_rois로 검사해48카드 모두 정답이었다. 기존정답39개는 그대로 유지했고, 미인식9개를 복구했다.

| 저장 사진의 게임 프리셋 경로 | dev5 정답/오확정/미인식 | dev6 정답/오확정/미인식 |
|---|---:|---:|
| 학습용8장·24카드 | 19 / 0 / 5 | 24 / 0 / 0 |
| 학습에 쓰지 않은8장·24카드 | 20 / 0 / 4 | 24 / 0 / 0 |
| 전체16장·48카드 | 39 / 0 / 9 | 48 / 0 / 0 |

사진은 이전 문제 발견 때도 살펴본 내부 회귀 자료다. 토나의 반복된 두 도형 패치는 픽셀까지 같다. 이 결과를 새 사진이나 모든40명의 인식 정확도라고 해석하면 안 된다.

## 왜 미인식이 생겼는가

얼굴과 정답 후보의 배경색은9건 모두 맞았다. 하단 영역에는 작은 도형 외에도 큰 문양의 꼬리와 배경 그라데이션이 섞여 있어, 패치 전체의 상관 점수가 도형의 정체성과 어긋났다. 도형 점수 실패4건, 비슷한 후보의 점수 차이 부족4건, 전체 상관 점수0.7484로 기준0.75에 못 미친1건이었다. 후보 점수 차이만 낮추면4건 중3건을 오확정한다.

대상5종은 엘리 빗자루 중참·칼날 휩쓸기·추가 작업, 토나 물줄기의 침식, 윌로(여름) 멈추지 않는 바다 소리다. 복구한9건 중4건은 목표0인 잠재력이며 제외 상태도 유지했다.

## 모델과 연결 방식

모델은32×32 도형 영역의 HOG324 특징→64개 은닉 노드→배경/마름모/삼각형/원형을 분류하는 MLP다. 파라미터21,060개, 정규화값648개, 압축된 가중치81,741바이트다. 기존 NumPy/OpenCV만 사용하므로 큰 학습 라이브러리나 GPU가 배포에 추가되지 않는다. 개발환경에서 HOG와 MLP 분류만 평균0.036ms로 측정했다. 화면 캡처·문양 탐색을 포함한 전체 처리 시간은 이 수치와 다르다.

원본 합성6,400개와 학습용8장·24개의 실제 도형 증강1,920개를30epoch 학습했다. seed는20261012다. 모델과 기준값을 고정한 뒤 나머지8장을 평가했고, 결과를 보고 가중치나 기준값을 다시 바꾸지 않았다. 사각형·십자·빈 영역·도형 없는 문양 등은 배경 학습에 포함했다. 클래스 분류 확신이 실제 정답 확률을 보장하거나 모든 처음 보는 도형을 거부한다는 의미는 아니다.

기존 인식이 확정된 경우에는 결과를 유지한다. 보류된 일반 잠재력에만 모델을 쓰고, 검증된 게임 프리셋의 역할 후보가 있어야 한다. 그림 NCC≥0.80, 전체 NCC≥0.65, 배경 hue 차이≤18, 도형 softmax≥0.95와 차이≥0.50을 함께 요구한다. 도형은 그림과 같은 위치에서 읽으며 모델 입력은 관측 픽셀과 영역 좌표뿐이다. 정답 PID·기대 도형·목표 레벨을 모델에 주지 않는다. 같은 시각 구성을 가진 여러ID나 비슷한 문양 후보는 계속 미확정이다. 복구된 결과의 표시 점수는 그림 NCC이며 확률이 아니다.

모델은 로드 시 해시·규격을 확인한 뒤 메모리에 고정한다. 모델이 없거나 손상되면 기존 인식 방식으로 동작한다. 색 없는 입력이나 손상된 이미지 메타데이터를 우회해 확정하지 않는다. 목표1~2/Lv.1 확보,3~5/다다익선,6/목표Lv.6,0/제외 해석은 유지했다.

## 범위와 재현

회귀 테스트114개가 통과했다. 독립 worker 재검사와 실제 실행 파일에 포함된 코드의 검사에서도48/48을 재현했다. 잘못된 색·다른 문양·배지 제거·역할 손실 등19개 구성 사례와, 학습에 사용하지 않은 별24개·오각형2개 구성 사례를 모두 미확정으로 처리했다. 이 유한한 합성 검사가 모든 미지 도형의 거부를 보장하지는 않는다. 역할 없는 기존 프리셋 경로는36정답·1오확정·11미인식으로 그대로이며, 이 모델의 복구는 게임 코드로 가져온 프리셋에 적용된다. 이미지 등록 범위는 얼굴33명·잠재력957개, 이번 보정 메타데이터는3캐릭터87개이고 실제 관측은31종이다. 다른 캐릭터·스킨·해상도·새 사진과 실시간 오버레이는 추가 확인이 필요하다. 현재 획득 레벨과 목표 달성 여부는 읽지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts/train_badge_model.py --output-dir ../new-badge-model
.\.venv\Scripts\python.exe scripts/benchmark_calibrated_matching.py --assets-dir ../calibration-v2-r3 --output ../new-worker-report.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

학습 명령에는 로컬 고정 사진/정답·공개 원본으로 만든 후보가 필요하다. 새 출력 폴더를 쓰며 사진이나 기존 모델을 덮어쓰지 않는다. 학습 출력은 실험 후보이며 앱 등록은 별도다. 위 benchmark는 앱에 등록된 models/badge-model.json과 가중치를 실제 worker로 읽는다. dev5와 최초 학습 후보의 JSON/가중치/스크린샷은 보존했다.
