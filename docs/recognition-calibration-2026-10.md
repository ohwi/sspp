# 인식 보정: 1.1.0-dev5

한국 서버 한글 화면에서 관측한 엘리·토나·윌로(여름) 3명의 인식을 보정했다. 저장된 사진 16장을 시간순 짝수 인덱스 8장(fit), 홀수 인덱스 8장(test)으로 먼저 나눴다. 실제 `MatcherWorker.process_rois`와 사용자의 게임 코드로 만든 `BuildLoader`를 연결했다. 게임 입력이나 실시간 캡처 없이 저장 픽셀을 사용했다.

| 게임 프리셋을 불러온 범위 | 카드 수 | 정답 | 오확정 | 미인식 |
|---|---:|---:|---:|---:|
| 맞춤용 8장 | 24 | 19 | 0 | 5 |
| 검사용 8장 | 24 | 20 | 0 | 4 |
| 전체 16장 | 48 | 39 | 0 | 9 |

얼굴은 맞춤용·검사용 각 24개 모두 정답이었다. 이전 생성 후보는 16개 정답 중 동일 픽셀 ID를 파일 순서로 고른 2개를 포함해, 그림만으로 구분됐다는 근거는 14개였다. 새 native 모드는 프리셋의 메인·지원 역할까지 사용하므로, 이 비교는 역할 제한을 포함한 전체 앱 동작의 개선이다.

## 구현

- 맞춤용 사진에서 65px 얼굴 3개를 추출하고 같은 캐릭터의 평균 masked SQDIFF로 기준을 선택했다. 검사용 사진에서 기준을 선택하거나 픽셀을 추출하지 않았다.
- 온라인 원본의 배경·glyph·Corner를 같은 위치에서 비교한다. 일반 카드는 하단 도형을 포함하도록 150×170, 핑크 전용 카드는 150×150으로 생성했다. 배경색도 확인한다.
- 검증된 게임 프리셋만 세 캐릭터와 각 역할의 16개 잠재력으로 후보를 좁힌다. 목표 0도 포함한다. 일부 선택 항목만 담긴 레거시/SSToy 빌드를 전체 역할 목록으로 간주하지 않는다.
- 동일 픽셀이나 충분한 점수 차이가 없는 후보는 미확정이다. 도형 검사에서 탈락한 비슷한 경쟁 후보도 점수 차이에 반영한다. 엘리 13/33은 검증된 역할이 있으면 구분하고, 역할이 없으면 미확정으로 남긴다.
- 전체 NCC 0.75, 얼굴 SQDIFF 0.15에 구성요소와 점수 차이 검사를 더했다. 이 수치는 정확할 확률이 아니다. 평탄한 얼굴 영역, 색 증거가 없는 보정 후보, 손상된 메타데이터·이미지 해시도 거부한다.

## 등록 범위와 남은 한계

앱 이미지는 얼굴 33명·잠재력 957개다. 이 단계에서는 위 세 캐릭터의 잠재력 이미지 87개를 등록했고, 관측된 31종을 사진 16장으로 검사했다. 87개 모두가 실제 선택 화면에서 확인됐다는 뜻은 아니다. 나머지 7명의 얼굴과 잠재력 203개는 생성 후보에 남아 있다. 카탈로그는 고정 공개 자료의 40명·1,160개이며, 한국 서버 전체 출시 목록과 모든 스킨의 완전성을 인증하지 않는다.

오확정 0은 **게임 프리셋의 역할 제한을 적용한 경로**의 결과다. 역할 정보 없이 비교한 레거시 경로는 같은 사진에서 정답 36개·오확정 1개·미인식 11개였다. 목표나 역할을 사진의 정답에서 가져와 주입하지 않은 실제 앱 신호를 집계했다.

사진 원본, 이전 v1·첫 v2·r2 후보와 기존 분석 결과는 보존했다. 빈 화면 0/128/255, 동일 그림 13/33의 미확정과 역할에 따른 구분, 이전 윌로 516021·516022·516023의 세 카드 유지도 별도로 확인했다. 사용자의 원래 목표 48개와 목표 0을 포함한 역할 후보도 그대로 유지했다.

검사용 8장도 이전 문제 발견 때 살펴본 자료이며 사진끼리 연속된 장면이 있다. 같은 분할로 보정을 반복한 내부 회귀 검사이고, 새 사진에서의 일반 성능을 입증한 결과는 아니다. 핑크 카드는 맞춤용 사진에 없어 이전 별도 윌로 화면의 변환을 승계했다. 다른 캐릭터·스킨·해상도와 실시간 오버레이는 추가 확인이 필요하다.

## 재현

로컬 입력은 `../screenshot-validation`의 사진 16장·inputs.json·ground-truth-a.json·ground-truth-b.json·이전 분석 결과, `../generated-templates`의 v1 원본 캐시와 manifest, `../asset-audit`의 고정 자료다. 사용자 전체 스크린샷은 저장소에 포함하지 않는다. 새 출력 폴더를 사용하며, 생성 도구는 다른 내용의 기존 후보를 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts/calibrate_face_templates.py --output-dir ../calibration-new
.\.venv\Scripts\python.exe scripts/calibrate_potential_templates.py --output-dir ../calibration-new
.\.venv\Scripts\python.exe scripts/benchmark_calibrated_matching.py --assets-dir ../calibration-new --output ../calibration-new/benchmark-report.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

생산 `templates/potential-manifest.json`은 등록된 87개만 포함하며 `faces-manifest.json`은 선택한 원본의 해시와 좌표를 남긴다. 후보 manifest의 290개(이전 누락 287개 + 윌로 기존 3개)와 앱 등록 범위를 구분한다. 같은 입력의 얼굴 도구를 새 출력 폴더에서 재실행해 세 PNG가 바이트까지 동일함을 확인했다.
